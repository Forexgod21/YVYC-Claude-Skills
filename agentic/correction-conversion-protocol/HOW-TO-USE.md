## What This Skill Does

Ends the re-issued correction. Every user correction converts to a
class-level standing rule — extracted, acknowledged once, applied
immediately, enforced for the session, and carried forward where
memory exists. The correction is the rule; the repeat is the failure.

## When It Activates

- Any user correction of behavior, format, tone, or approach
- Designing feedback-integration behavior for agents
- Diagnosing why an AI keeps making the same mistake
- "Stop doing X" / "I already told you Y" / "again?"
- Building correction persistence into memory-equipped systems

## Installation

1. Create a folder named `correction-conversion-protocol` in your
   Claude skills location.
2. Place `SKILL.md` inside it.
3. Claude activates it automatically when corrections occur or
   correction-handling is being designed.
4. Pairs with `authority-stack-doctrine` — persisted rules live at
   the memory layer and obey the stack.

## Example Invocations

> "Stop putting headers in short answers."

The conversion, live: class extracted (formatting weight scaled to
response length, not headers-in-this-one-reply), acknowledged in one
line, current response already compliant, rule active for the session.

> "Why am I correcting this again?"

The repeat tripwire: explicit acknowledgment that the rule failed to
hold, what changes in enforcement — not a fresh first-time apology
that pretends the earlier correction never happened.

> "Design how my agent should handle user feedback."

The full protocol as architecture: extract-acknowledge-apply-enforce,
class-scope discipline, the no-relitigating rule with its single
safety exception, the repeat tripwire, and the persistence pathway
with scope attached.

## What You Get

- Corrections that hold — session-long and beyond
- Class-level fixes instead of instance patches
- One-line acknowledgments instead of apology theater
- A standing profile of rules that compound instead of evict
- A tripwire that treats repeats as the failures they are

## What This Skill Will Refuse

- Fixing the instance while ignoring the class
- Debating or relitigating a correction
- Multi-sentence contrition
- Letting rule seventeen evict rule three
- Making the user issue the same correction in a fourth session
