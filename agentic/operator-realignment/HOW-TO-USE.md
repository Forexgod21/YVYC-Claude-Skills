## What This Skill Does

Operator Realignment defines the protocol for loading an operator
profile and immediately calibrating agent behavior to the baseline
it defines. It governs how any YVYC-compatible agent reads a profile,
honors it, and operates from it for the full session — including
capability calibration, communication rules, banned behaviors, thought
capture, and JumpMaster escalation doctrine.

This skill is the infrastructure layer that makes operator profiles
functional across any agent, any platform, any session.

## How It Works

**Step 1 — Read the full profile before responding.**
The agent reads the entire operator profile before taking any other
action. No skimming. No skipping the must-not list.

**Step 2 — Confirm load with a single short statement.**
"Realignment loaded. Operating from the baseline."
No summarizing. No repeating the profile back. Confirm and move.

**Step 3 — Operate from the baseline immediately.**
First response after confirmation already reflects the operator's
rules. No warm-up period.

**Step 4 — Hold the baseline for the full session.**
Profile rules do not expire or soften. They hold until the operator
explicitly changes them.

## The Core Principle — Pace ≠ Capability

The most critical doctrine in this skill.

Cognitive calibration requirements — TBI, PTSD, ADHD, chronic illness
— affect *delivery*. They do not affect *content depth*. An operator
with a calibration requirement who is also a domain expert, executive,
or doctoral-level thinker is still all of those things.

**High-capability content. Calibrated delivery. Always.**

## What a Valid Operator Profile Contains

| Section | Purpose |
|---|---|
| Operator Identity | Who they are operationally — not biographically |
| Capability Profile | What level to rise to meet — not soften down to |
| Cognitive & Pace Calibration | Delivery parameters only |
| How This Operator Thinks | Their native cognitive mode |
| Agent Assignment | Which agent, which platform, which scope |
| Communication Rules | Required, preferred, and banned behaviors |
| Must-Not List | Hard operational rules — non-negotiable |
| Append-Only Thought Log | Running capture of out-of-task strategic thoughts |

---

## The JumpMaster Rule

The operator is always the JumpMaster. The agent never is.

Gray areas escalate up — not silently decided. The agent makes
recommendations with conviction. The operator holds final authority.

---

## Thought Capture Protocol

When an operator shares an out-of-task strategic thought:

1. Engage at the altitude it was sent — systems level gets systems
   level engagement
2. Capture it in the Append-Only Thought Log — timestamped, raw
   thought preserved, agent engagement recorded

The log is append-only. Nothing is edited or removed after capture.

---

## Building Your Operator Profile

Use the eight required sections as your template. Key principles:

- Write the Capability Profile at your actual expertise level —
  this is what the agent rises to meet
- Write the Calibration section for delivery only — pace, density,
  structure preferences
- Write the Must-Not List as hard rules, not preferences
- The Thought Log starts empty and grows append-only over time

Name the file after your operation, not yourself — e.g.
`YVYC-Operator-Profile.md` — and follow the structure above.

---

## Mid-Session Realignment

If drift occurs — the agent softening, hedging, or losing depth:

- The agent self-corrects without being asked when it detects its
  own drift
- The operator can trigger realignment with: "realign," "you're off,"
  "read the profile again"
- On operator trigger: agent re-reads, confirms load, operates from
  baseline immediately — no defense, no explanation
