## What This Skill Does

Moves delegation safety from the whiteboard to the moment of handoff.
Every runtime delegation act passes a five-check gate — capability,
authority, state, boundary, recovery — with explicit bounded authority
transfer, accountability that propagates to the correct point in the
chain, human retention rules enforced live, and a delegation ledger
that improves the gate itself over time.

## When It Activates

- Multi-agent systems where agents delegate during execution
- Dynamic sub-agent spawning and mid-mission handoffs
- Designing delegation safety checks
- Post-incident review of a delegated task gone wrong
- Any system where "which safeguard should have caught this" has no
  answer

## Example Invocations

> "My orchestrator spawns sub-agents dynamically — how do I keep that
> safe?"

The two-level model installed: design-time rules for what KINDS of
delegation are permitted, plus the five-check runtime gate on every
individual act — because a delegation that was safe in architecture
review executes in conditions the review never saw.

> "A sub-agent took an action the main agent was forbidden to take."

The boundary check, named as the missing control: delegation never
launders a prohibition into permitted-by-distance. The gate blocks
any task that would exit the delegator's own operating boundaries,
no matter how many hops it travels.

> "Our agents delegate fine in testing and fail in production."

State check diagnosis: capability is static, condition is not — a
qualified delegatee under load, error accumulation, or resource
exhaustion is not qualified right now. Plus the ledger review that
catches gate checks measuring the wrong thing.

> "Who's at fault when a delegated task fails?"

Accountability propagation: bad decision, bad execution, or bad
specification — three different defects, three different owners,
attributed with the gate's evaluation record as evidence.

## What You Get

- A safety check that runs where failures actually happen: at runtime
- Authority transfers that are explicit, bounded, and time-limited
- Failure attribution that lands on the correct link in the chain
- Human decision points that hold under autonomous pressure
- A delegation ledger that turns every handoff into calibration data

## What This Skill Will Refuse

- Treating design approval as runtime clearance
- Delegating authority the delegator does not hold
- Prohibition laundering through sub-agents
- Open-ended authority grants without written justification
- Lowering delegation thresholds when visibility degrades
